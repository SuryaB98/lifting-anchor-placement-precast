An AI agent that places lifting anchors on a precast element

Build a proof-of-concept agent that ingests a precast wall, applies a fixed set of engineering rules, and generates and places the lifting anchors — with a per-anchor check report it can defend to a checking engineer.

Role: Software / AI Engineer Suggested effort: ~1 focused day Stack: your choice Element: WC001 v1.0

You do not need to be a structural engineer. Every rule, factor and capacity number you need is in this brief (§3 and the appendices). We are assessing how you turn a safety-critical rule-set into a reliable, explainable agent — and your judgement about where an LLM belongs and where it must not.

Read first — safety framing This is a POC on the provided synthetic data only. Lifting design is genuinely safety-critical — a wrongly placed or undersized anchor can drop a multi-tonne panel onto people. Nothing you build here is for real fabrication. The whole point of the exercise is to see whether you treat a life-safety rule-set with the discipline it deserves: deterministic maths, explicit checks, and failing closed when an input is missing rather than guessing.

1 · Context — what we're building and why it matters

BuildTwin builds an AI cockpit for precast concrete. Every precast element is cast in a mould, stripped, turned from flat to vertical, transported and finally erected on site. To be handled at all, the element has steel lifting anchors cast into it. Where those anchors go — how many, in what position, of what capacity — is decided by deterministic engineering rules and the anchor manufacturer's approval tables. It is unforgiving: the wrong position makes the panel hang out of plumb and overload one anchor; the wrong capacity or concrete strength pulls the anchor out of the concrete.

Today our prototype does this with a naive heuristic: it puts two anchors at 20% of the length from each end and stops. It has no centre of gravity, no load cases, no capacity check, no awareness of openings, and no notion of when to refuse. We want to find out whether an AI agent that orchestrates the real rules can place the anchors properly, show its working, and know when it must hand back to a human. That is your task, on one real element: WC001.

3 · The rules — your engineering specification

This is the rule-set your agent implements. It is deterministic: given frozen inputs there is exactly one correct answer. You do not need to derive any of it — the factors and capacities are tabulated below.

3.1 · How the force on each anchor is computed

Two anchors carry the panel (n = 2), and they are statically determinate, so each carries half of the factored load — but you must check the worst share, not assume a perfect 50/50 if the centre of gravity is off-centre. For each handling state:

# transport / handling / erection
F_per_anchor = G * ψ_dyn * z / n
# demould adds formwork adhesion over the cast face A_f = L × H
F_per_anchor = ( G * ψ_demould + q_adh * A_f * ξ_adh ) * z / n

G self-weight · ψ_dyn dynamic factor (§3.2) · z sling-angle factor (§3.4) · q_adh adhesion 1.0 kN/m² · ξ_adh = 1 for a flat solid panel · n = 2.

3.2 · Load cases — each is checked at its OWN concrete strength

Erection (crane)1.4@full——
The single most common mistake Transport has the biggest dynamic factor but happens at full strength; demould has a smaller factor but happens at 15 MPa, when the anchor's capacity is much lower. You must match each case to the right strength column. The governing case is whichever gives the highest demand-÷-capacity ratio — and it is not always the heaviest load.

3.4 · Sling angle

A non-vertical sling at angle β from vertical multiplies the anchor force by z = 1/cosβ ( z = 1.00 / 1.04 / 1.16 at β = 0° / 15° / 30° ) and adds a transverse pull of F·tanβ checked against V_zul. Keep β ≤ 30°. A spreader beam makes the slings vertical (β = 0, no transverse pull) and is required whenever a straight sling would exceed the angle limit, or the panel is thinner than the anchor's transverse min-wall.

3.5 · The placement procedure (deterministic, ordered)

1. Enumerate the handling states for the element and its production method. Turn method is a hard input — if UNCONFIRMED, also run the free-crane-turn weak-axis check and hold.
2. Compute the per-anchor force for every state (§3.1), each at its own strength column (§3.2). Keep the worst.
3. Fix n = 2. Both anchors are safety-critical; n = 2 is the load basis, not a spare. More than two anchors still counts as two unless a load-balancing beam is used.
4. Compute the centre of gravity including openings (and a note for the one-sided curtain). Require the panel to hang plumb: the lift line passes through the CoG, CoG below the picks.
5. Trial position a = 0.207·L from each end (the balance point that minimises panel bending). Trial only.
6. Shift the anchors to keep it plumb about the real CoG. For an asymmetric / opening-weakened panel, symmetric-about-mid-length is not enough.
7. Enforce edge distance, axis spacing and min wall thickness from the catalogue (§3.3). The catalogue wins over the 0.207·L position.
8. Enforce clash clearance — anchor + its supplementary reinforcement must clear the curtain, opening trimmers and other cast-ins, and not land on an opening void.
9. Check capacity F ≤ N_zul per anchor, at the matched strength column, axial and transverse.
10. Decide rig: spreader vs direct slings from the angle and the transverse min-wall (§3.4).
11. Decide outcome: ACCEPT (provisional) if all pass · ITERATE (move in, raise strength, upsize, add spreader) · HOLD if no solution or any input is missing/contested.
12. Never auto-release. Output is always provisional and is flagged for a named human to countersign.

3.6 · Hard stops (your agent must enforce these, fail-closed)

  • No finalised placement against unresolved geometry (the §2 conflict) or an UNCONFIRMED turn method — emit a provisional result + an RFI.
  • No capacity read at the wrong strength column; no lift below the specified first-lift strength.
  • No anchor whose min wall thickness exceeds the panel thickness for the load direction in play.
  • No assuming > 2 anchors share the load without a balancing beam.
  • No mismatched anchor/clutch; no tabulated capacity claimed without the supplementary reinforcement.
  • The agent itself never signs off — it always routes to a human.

The 180 mm panel is thinner than the ARL-42 transverse min-wall (240 mm) → the pull must stay axial, which forces a spreader beam.

4 · Your task

Build a proof-of-concept AI agent that takes the WC001 element data (Appendix A), applies the rules of §3, and produces a placed, checked, explainable lifting-anchor design. Concretely, given the element it must:

  1. Generate & place the anchors — choose the anchor type and count, and output an (x, y) position for each on the panel.
  2. Show the check — for each handling state, the per-anchor force, the capacity at the matched strength, the utilisation, pass/fail.
  3. Explain itself — a short, auditable justification that cites which rule drove each decision, plus any RFIs (e.g. the geometry conflict, the unconfirmed turn method).
  4. Fail closed — when an input is missing or contradictory, return a HOLD with the reason and the conservative interim assumption, never a confident wrong answer.
  5. Visualise it (light) — a simple 2D elevation of WC001 with the anchors drawn where the agent put them. A static SVG/PNG/HTML is fine.

6 · The part we care most about — where the AI belongs

The determinism boundary — this is the core of the assessment Safety-critical arithmetic and pass/fail decisions must be deterministic, testable code. The LLM must not compute a force, read a capacity, or decide a pass/fail by reasoning in prose. If a model hallucination can change a safety number, the design has failed. We will look specifically for this line being drawn cleanly.

Good jobs for the LLM agent

  • Ingesting and normalising messy / conflicting input.
  • Deciding which rule branch or case applies.
  • Orchestrating the tool calls and the iterate loop.
  • Writing the human-readable justification & RFIs.
  • Choosing accept / iterate / escalate within the rules.

Must stay deterministic (tools/code)

  • Self-weight, per-anchor force, adhesion, angle factor.
  • Centre of gravity from geometry + openings.
  • Capacity lookup at the matched strength column.
  • Edge / spacing / thickness / clash checks.
  • The final F ≤ N_zul pass/fail and utilisation.

A natural shape is an LLM agent with a set of typed tools (compute_cog, per_anchor_force, lookup_capacity, check_placement) where the agent reasons about what to do and the tools do the maths. Any framework (or none) is fine — we care about the boundary, not the library.

Appendix B · Glossary (for the non-structural reader)

TermPlain meaning
Lifting anchorA steel insert cast into the concrete that a crane clutch hooks onto to lift the element.
Demould / stripLifting the element out of its mould — the earliest, weakest-concrete lift.
Centre of gravity (CoG)The balance point of the element's mass; openings move it. The element hangs plumb only if the lift line passes through it.
Balance point (0.207·L)The pickup position that minimises bending in the element when lifted as a beam.
Dynamic factor (ψ)A multiplier on self-weight for the jolts of a given operation (transport bounces hardest).
Spreader beamA bar above the element that keeps the slings vertical, removing sideways pull on the anchors.
Supplementary reinforcementExtra steel around the anchor; without it the anchor's rated capacity does not apply.
UtilisationDemand ÷ capacity. ≤ 1.0 passes; the closer to 1.0, the less margin.
RFI"Request for information" — the formal way an engineer flags missing/contradictory input instead of guessing.
PrüfingenieurAn independent checking engineer (German practice) who must be convinced the design is safe before it is built. Imagine your output has to satisfy one.
